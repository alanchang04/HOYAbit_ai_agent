### 整體流程

```text
                                  User Query
                                       │
                                       ▼
                          Query Understanding Layer
                                       │
      ┌────────────────────────────────┼────────────────────────────────┐
      │                                │                                │
      ▼                                ▼                                ▼
 Asset Extraction              Time Horizon                  Research Goal
(BTC / ETH / XRP...)      (1D / 1W / 2W / 1M...)    (Trend / Event / Risk)
      │                                │                                │
      └────────────────────────────────┴────────────────────────────────┘
                                       │
                                       ▼
                           Research Orchestrator
                                       │
         ┌─────────────────────────────┼─────────────────────────────┐
         ▼                             ▼                             ▼
 Price Collector               News Collector              On-chain Collector
 Macro Collector               Social Collector            Market Collector
         └─────────────────────────────┬─────────────────────────────┘
                                       │
                                       ▼
                             Raw Evidence Collection
```

跟 Round 6 一樣，**Query Understanding Layer 是新增的最上游一層**——Round 6
沒有明確處理「這個 Query 該看哪個時間尺度」，這輪把 Time Horizon 判斷提到
最前面，跟 Asset Extraction／Research Goal 平行拆解，而不是留給後面某一層
隱含判斷。

### Stage 1 — Evidence Validation

回答「這筆資料可信嗎？」，跟 Round 6 的第一層同名同性質，沒有變動：

```text
Raw Evidence
      │
      ▼
Evidence Validation
      │
      ├── Source Reliability
      ├── Timestamp Validation
      ├── Cross-source Validation
      ├── Missing Data Check
      └── Data Integrity
      │
      ▼
Validated Evidence
```

### Stage 2 — Feature Extraction

回答「資料本身告訴了我們什麼？」，這一層**完全沒有 Interpretation，只有
Fact**——這是跟 Round 6 的差異之一：Round 6 的 Factor Interpreter（第二層）
直接從 Validated Evidence 跳到 Financial Interpretation（含 `Claim`／
`Direction`），這輪先插一層純粹的事實抽取，把「抽特徵」和「做金融解讀」
拆成兩步。

```text
Validated Evidence
        │
        ▼
Feature Extraction
```

例如：

```yaml
Funding:
  Funding: 0.08%
  Percentile: 97th
  Trend: 7-day Increasing

OI:
  OI: +18%
  Trend: 3-day Increasing

News:
  Event: ETF Approval
  Tone: Positive
```

### Stage 3 — Knowledge Layer

這一層不是推理，是「這個 Factor 本身有哪些金融知識」——**這是本輪新拆出來
的獨立層**，Round 6 沒有這一層，金融知識判準（例如「Historical Support」）
是直接混在 Evidence Card 欄位裡的。

```text
Extracted Features
         │
         ▼
Knowledge Layer
         │
         ├── Statistical Knowledge
         ├── Event Knowledge
         └── Sentiment Knowledge
         │
         ▼
Knowledge Metadata
```

例如 Funding 的 Knowledge Metadata：

```yaml
Historical Support: ...
Primary Horizon: ...
Typical Confirmation: ...
Common Failure Conditions: ...
Evidence Scope: ...
References: ...
```

明確禁止出現 Bullish／Bearish／Trend Continuation 這類方向詞——Knowledge
只是 Prior，不是結論。

### Stage 4 — Dynamic Evidence Weight Engine

把 Weight 獨立出來，回答「今天這筆 Evidence 有多重要？」——Round 6 沒有
獨立的 Weight 引擎，重要性判斷是揉進 Evidence Prioritizer 的
`Base Importance`／`Context Modifier` 兩個欄位；這輪把「先驗重要性」跟
「今日情境調整」拆成兩層，公式化：

```text
Evidence
      │
      ▼
Evidence Weight Engine
      │
      ├── Prior Weight（來自 Knowledge：Historical Support／Source
      │   Reliability／Historical Predictability）
      │
      └── Dynamic Modifier（來自今日市場：Market Regime／Time Horizon
          Match／Context／Cross-source Consensus／Freshness）
      │
      ▼
Final Evidence Weight = Prior Weight × Context Modifier
```

### Stage 5 — Evidence Card

所有 Evidence 統一格式：

```yaml
Evidence ID
Category
Fact
Features
Knowledge
Evidence Weight
Source Reliability
Historical Support
Primary Horizon
Persistence
Decay Pattern
Evidence Scope
Related Evidence
Failure Conditions
Traceability
```

**跟 Round 6 的關鍵差異**：Round 6 的 Evidence Card 有 `Claim`／`Direction`
兩個方向性欄位，這輪整份拿掉，改成新增 `Evidence Weight`（取代原本分散的
`Base Importance`／`Context Modifier`）跟 `Evidence Scope`（見文末新增
概念）。

### Stage 6 — Evidence Prioritizer

回答「哪些 Evidence 最值得討論？」，跟 Round 6 的 Evidence Prioritizer
精神一致（不是刪掉，只是決定討論順序），但排序輸入换成用 Stage 4 算好的
`Evidence Weight`，而不是 Round 6 那五個獨立輸入：

```text
Evidence Cards
       │
       ▼
Evidence Prioritizer
       │
       ├── Evidence Weight
       ├── Time Horizon Match
       ├── Evidence Coverage
       ├── Cross-source Consensus
       └── Freshness
       │
       ▼
（排序，不刪除）
```

### Stage 7 — Evidence Graph

跟 Round 6 同名同性質，沒有變動——只存 Evidence 之間的關係
（supports／conflicts／independent／requires），不含市場方向：

```text
Funding ── supports ──▶ OI
ETF ── conflicts ──▶ Funding
```

## Stage 4 — Dynamic Evidence Weight Engine（示範：ATR）

> 對應 [[07_流程圖迭代定案]] Round 7 的 Evidence Weight Engine。
> ATR 的 Market Regime 若用 ATR 自己的歷史序列判斷會自我循環，
> 改用「降息與否」（FOMC 利率決議方向）當外部依據，避免自己量自己。
>
> **Dynamic Modifier → context_modifier**：不用公式連乘，改由 LLM 讀取
> market_regime／time_horizon_match／context 這幾個線索，解釋並給出一個
> context_modifier 數字（含理由），再乘以 Prior Weight 得到 Final Weight。

```
weight:
  factor_id: ATR

  ####################
  # Prior Weight（來自 Knowledge，慢變動）
  ####################
  historical_predictability:
    ic:                          # 原始 IC 值，直接用（例如 Funding=0.11／OI=0.18／Social=0.02）
    # hit_rate:                  # HitRate 資格門檻邏輯，待定，先註解
    # normalization:             # 正規化公式，待 Ken 校準，先註解
  # source_reliability:          # 待來源可信度分級表定案，先註解
  # historical_support:          # 對應 references 欄位怎麼轉成分數，待定，先註解

  ####################
  # Dynamic Modifier（來自今日市場，快變動——餵給 LLM 當線索，不套公式）
  ####################
  market_regime:
    classification:              # rate_cutting／rate_hiking／rate_hold 三態，資料來源＝FOMC 利率決議方向
  time_horizon_match:            # 計算規則待補（Ken 說等等處理）
  context:                       # 具體指什麼還沒定義

  context_modifier:              # 由 LLM 根據上述線索解釋給出，非公式計算
  final_weight:                  # = prior_weight × context_modifier（LLM 給的數字）
```

## Stage 4 — Dynamic Evidence Weight Engine（示範：funding_rate）

> Market Regime 沿用 ATR 那份的定義（降息與否，FOMC 利率決議方向）。
>
> **Dynamic Modifier → context_modifier**：不用公式連乘，改由 LLM 讀取
> market_regime／time_horizon_match／context 這幾個線索，解釋並給出一個
> context_modifier 數字（含理由），再乘以 Prior Weight 得到 Final Weight。

```
weight:
  factor_id: funding_rate

  ####################
  # Prior Weight（來自 Knowledge，慢變動）
  ####################
  historical_predictability:
    ic: 0.11                     # 示範值
    # hit_rate: 0.63             # 示範值，先註解
    # normalization:             # 正規化公式，待 Ken 校準，先註解
  # source_reliability:          # 待來源可信度分級表定案，先註解
  # historical_support:          # 對應 references 欄位怎麼轉成分數，待定，先註解

  ####################
  # Dynamic Modifier（來自今日市場，快變動——餵給 LLM 當線索，不套公式）
  ####################
  market_regime:
    classification:              # rate_cutting／rate_hiking／rate_hold 三態，資料來源＝FOMC 利率決議方向（沿用 ATR 定義）
  time_horizon_match:            # 計算規則待補（Ken 說等等處理）
  context:                       # 待定

  context_modifier:              # 由 LLM 根據上述線索解釋給出，非公式計算
  final_weight:                  # = prior_weight × context_modifier（LLM 給的數字）
```
